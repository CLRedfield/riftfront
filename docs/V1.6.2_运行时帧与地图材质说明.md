# V1.6.2 运行时帧与地图材质说明

## 1. 为什么只看原图会误判

7 张单位源图均为 887×1774，看上去接近 4 列×8 行，但不能安全地直接等分：

- 单列宽度为 221.75 像素、单行高度为 221.75 像素；
- 泰坦、蜂巢 Boss、棱镜巨像和攻击特效会跨出名义行；
- 旧代码按 `naturalHeight / 8` 裁切后，可能得到“本行角色下半身 + 下一行角色头部”；
- 缩到战场尺寸后，这种串行看起来就像角色被上下翻转或重新拼装。

因此本次诊断以局内最终 canvas 为准，而不是以源 PNG 为准。

## 2. 运行时审计页

启动本地服务器后打开：

```text
http://localhost:8000/tools/runtime_sprite_audit.html
```

审计页直接读取 `RF.UNIT_SPRITE_RUNTIME`，复用游戏的图集路径、卡牌到行映射、整数裁剪函数和敌方 X 轴镜像。每行依次显示静止、移动、攻击与敌方向收势帧。

## 3. 规范图集构建

`tools/build_runtime_sprite_atlases.cjs` 的处理流程：

1. 在名义行上下扩展 64% 行高取样；
2. 读取透明通道并计算 4 邻域连通域；
3. 以面积与到目标行中心的距离共同评分，选择真正的单位主体；
4. 同一单位四帧计算共同边界、共同缩放与共同锚点；
5. 输出严格 888×1776 图集，每帧固定 222×222。

最终局内只读取 `assets/sprite_sheets_runtime/`，不在战斗中执行像素分析，避免首次部署卡顿，并保持 `file://` 离线模式兼容。
